Agent-Native 因子研究

Assay 为外部 Agent 提供持久研究状态与因子执行工具。模型、提示词和探索策略由调用方选择， 研究状态不绑定特定 LLM 或多 Agent 流水线。

对象 内容与语义
Dataset 固定股票池、日频区间、知识截止日、收益期限、执行模型、复权与后端名称
Research Session 研究目标、发起 Agent、尝试次数预算、持久笔记和实验历史
Experiment 独立尝试 ID、请求 ID、假设、表达式、父实验、状态、完整评估报告或异常

本地或服务密钥工作区位于 <data_dir>/research/workspace.sqlite3。现有 assay.Session 是临时计算面板缓存， 研究会话独立于该缓存，重启服务后仍可读取。

Python 示例

离线体验：PYTHONPATH=src python scripts/demo_agent_research.py。脚本生成合成行情，调用真实评估器， 保留失败实验、重建服务，再以第二个模拟 Agent 客户端接续研究。它验证生命周期，不代表已验证真实 LLM 兼容性。

安装依赖并按快速上手准备行情后：

import assay

assay.init()
ws = assay.research_workspace()
dataset = ws.register_dataset(
    "nasdaq-reversal-2024", "NASDAQ100", ["2024-01-01", "2024-12-31"],
    horizons=[1, 5, 10], execution="next_open", adj="split",
)
session = ws.create_session(dataset["id"], "研究短期反转", agent="agent-a", max_experiments=20)
attempt = ws.evaluate(
    session["id"], "-cs_rank(ts_returns(close,5))", "近期涨幅较大的股票可能短期回落",
    request_id="reversal-5d-01", agent="agent-a",
)
ws.add_note(session["id"], "下一轮比较更短的回看窗口", agent="agent-a")
print(attempt)

重启或切换 Agent 后，用 ws.list_sessions() 发现会话，使用 ws.get_session(id) 读取目标、 配置、笔记、成功和失败实验及剩余预算。新尝试可用 parent_id 指向同一会话中的旧实验。 ws.compare_experiments([id1, id2]) 返回指标、失败信息和配置是否一致，不丢掉失败行。

读取区间、评分区间与表达式约束

period 是行情读取范围，包含预热和前瞻标签缓冲。可另设 score_period 与预先核验并冻结的 score_dates，使报告顶部 IC/RankIC 只统计指定交易日；目前显式评分区间支持单一 horizon。 日期缺失、乱序、序列不齐或评分为空会保留为 INCOMPLETE_SCORE_COVERAGE，不回退到面板总体指标。

实验的 report 是区间内指标，panel_report 单独保留后端原始证据。无法仅凭每日 IC 重算的 换手率、分组收益和衰减会置空，避免继续展示预热区间的汇总值。

Dataset 还可指定 expression_policy：fields、operators、max_window 和 max_cumulative_lookback。工作区在调用后端之前，检查字段、算子和嵌套窗口；拒绝的候选 保留为失败尝试并计入次数预算，但不会执行行情评估。评分范围和约束均参与配置哈希，SDK/MCP 使用同一契约。 窗口预算沿用 AlphaBench 稳定 OHLCV 语法的规则，不代表 EMA 等递归滤波器只有有限历史依赖。 读取范围仍需显式包含足够预热和标签缓冲，注册接口不会自动下载或推导额外行情。

因子选择与组合回测

新注册的内置 assay 数据集在次日成交模式下，默认同时运行因子诊断与组合回测。 report.portfolio 保存成本后净值、收益、Sharpe、回撤、实际交易换手与成本拖累。 注册时可用 portfolio={"rebalance_type": "weekly"} 固定回测参数；参数参与数据集哈希。 portfolio={"enabled": False} 仅运行因子诊断，显式 IC 评分窗口与同日 close 模式默认如此。 已有数据集保留原配置。缺少冲击成本输入、资金规模或持仓报价时，报告会给出具体记录。

每个可解析的实验与规范化因子在同一个 SQLite 事务中登记。目录复用 FactorDB Registry， 同一因子可以关联多次实验及多个研究会话；完整报告保留在实验历史中，目录的最新分数仅供检索。

ws.decide_candidate(second["id"], "accepted", "保留较短窗口继续研究",
                    request_id="select-shorter", agent="agent-b")
print(ws.list_candidates(session["id"]))
print(ws.factor_history(second["factor_id"]))

选择状态包括 candidate、accepted、rejected、archived，按研究会话分别维护。 每次决定追加保存证据实验、理由、作者和幂等请求标识；采纳必须有完成的实验作为依据。 决定不消耗实验预算，随会话重启续接、导出及恢复；淘汰和归档的因子不会出现在交接上下文的活跃候选中。 MCP 提供 assay_candidate_decide、assay_candidate_list、assay_factor_history， Workbench 可查看组合指标并通过同一 REST 状态记录人工决定。

fdb_query、fdb_factor 默认通过 source="all" 查询研究目录和已配置的计算目录，也可指定 research 或 compute。计算提交和节点存储仍需配置 FactorDB/ADES，查询入口不会复制节点或合并物理数据库。

次日开盘成交时，旧持仓承担隔夜收益，成交后持仓承担日内收益；next_close 的 IC 标签和组合成交均从次日收盘开始。 新配置记录 evaluation_protocol="assay-daily-v2"，旧 next_close 数据集须重新注册，历史报告仍可读取。 计算评分缓存也区分执行语义版本。面板内容哈希包含行情、历史成分和分组标签，防止修订数据误用缓存。 预计算子表达式保留入池前的滚动历史，横截面计算与最终输出按当日成分筛选。

可运行 scripts/validate_research_loop.py --data-root PREPARED_STORE --output NEW_DIR， 在已有真实行情上验证完整闭环、重启恢复、独立现金／股数账本对账，并输出原始数据和实现哈希。 完整研究实验耗时、首次因子矩阵计算、共享面板/CSE 批量计算和精确缓存命中分别报告。 矩阵计算吞吐不等同于完整回测吞吐；独立账本验证已记录成交下的净值核算，选股规则和供应商数据完整性需另行检验。

搜索 checkpoint 与跨窗口任务

Agent 可以将自己的 MCTS 树、EA 种群、代数和随机状态组织为 JSON，按 session 和名称保存为追加式 checkpoint。Assay 保存数据，不自动序列化或执行客户端的算法对象。状态中不要保存密钥。

context = ws.research_context(session_id)
saved = ws.save_checkpoint(session_id, 'search', 'mcts',
    {'nodes': [{'experiment_id': experiment_id, 'visits': 3}], 'rng': [1, 2]},
    request_id='checkpoint-1', expected_revision=0,
    expected_state_revision=context['state_revision'])
restored = ws.get_checkpoint(session_id, 'search')

expected_revision 防止并发覆盖；可选的 expected_state_revision 防止读取后研究状态已变化。超时后复用相同请求 ID 和输入。恢复结果会指出 session 状态是否改变，以及新增或改变状态的实验；运行中实验需要单独恢复或取消。单个状态上限为 1 MiB，session 导出包含 checkpoint。记录的实验水位不能证明算法状态已处理了所有实验。

Program 将不同数据窗口的 session 关联到一个研究任务，每个 session 保留自己的数据配置和预算：

program = ws.create_program('momentum', 'Study signal persistence', request_id='program-1')
ws.attach_program_session(program['id'], train_session_id, label='train')
ws.attach_program_session(program['id'], later_session_id, label='later')
result = ws.reassess_program_factor(program['id'], source_experiment_id,
                                    later_session_id, request_id='later-1')
history = ws.program_factor_history(program['id'], result['attempt']['factor_id'])
pool = ws.program_candidates(program['id'])
comparison = ws.compare_program_windows(program['id'], source_experiment_id,
    result['attempt']['id'], drop_threshold=0.02)

重新评估使用目标 session 的数据与预算，并记录来源；历史列表返回每次的窗口、设置和指标。跨窗口比较要求时间有序、评分窗口不重叠及设置一致，并按调用方指定的 RankIC 下降阈值给出提示。评分日期不重叠不代表前向收益标签在后续窗口前已经可用，也不能证明设置了交易日缓冲；提示不构成统计意义上的衰减检验。Program 关联保存在工作区数据库中；单个 session 的导出只包含该 session 和 checkpoint，不含 program 关联。行情快照需要单独保存。

Program 因子池按规范因子身份汇总尝试，保留各 session 独立的接受／拒绝决策。MCP 对应 assay_checkpoint_save/get/list 和 assay_program_create/list/get/attach_session/candidates/reassess/factor_history/compare_windows；REST 路径见 REST API。

建议流程：发现可用股票池 → 注册数据集 → 创建或恢复会话 → 查看已有尝试 → lint → 执行实验 → 检查指标与诊断 → 保存判断 → 决定修订、调用已有组合回测工具或停止。下一轮决策由外部 Agent 驱动。

assay_experiment_get(id) 现在默认返回精简摘要。查看明细时指定 section="trades"、"positions"、"nav"、"ic" 或 "diagnostics"， 并传入 offset 和 limit（1–100）；结果包含 total 与 next_offset。 这避免大规模交易明细占满模型上下文。Python workspace 与 REST 实验接口仍返回完整报告。 长会话应优先使用 assay_research_context 向模型提供上下文；session export 和完整会话 接口用于存储及分析完整证据。assay_factor_history 同样接受 offset 与 limit， 按时间顺序分别截取实验、决定列表，history_page 给出两类记录的总数。

重试、预算与恢复

每次尝试指定稳定的 request_id。重复提交只返回旧状态，不重复执行；相同请求 ID 搭配不同 表达式、假设或父实验会报错。新请求 ID 代表新尝试，相同因子的不同实验不互相覆盖。 SQLite 事务在执行前预留预算，并发进程也不能超出次数上限；失败和放弃的实验均计入预算。

状态为 running → completed/failed；显式恢复可将 running 改为 abandoned。 completed 仅代表评估器未返回失败模式，不代表因子有效或盈利。 进程退出会留下 running 记录。确认旧 worker 停止后，用 abandon 工具记录原因， 再用新请求 ID 重试。修改记录不负责终止正在运行的后端。

后端与复现边界

用 ws.register_backend(name, backend) 注册实现 evaluate(expr, dataset) -> dict 的评估器， 返回 JSON 安全的因子报告。状态保存后端名称，后端对象与凭证不落盘，重启后需重新注册。 该接口可用于后续连接 QFV；这次没有实现 QFV 完整执行适配器。

自定义数据集可指定参与配置哈希的 backend_options。内置后端拒绝未支持的设置。 可选的 AlphaBenchBackend 复用 AlphaBench V2 的 REST 客户端，连接带补丁的 localhost:8002， 核对股票池冻结日期、股票轴哈希/数量与数据截止日，再向 Agent 提供分数。 跨仓库复用及真实 MCP 测试说明见 AlphaBench 复用测试。

Dataset 固定的是配置，不下载数据、不冻结行情。spec_hash 是配置的 SHA-256，不包含行情 内容、后端代码和模型版本。配置一致不等于不可变快照复现。内置 Assay 后端不支持解析快照 ID， 会拒绝指定 snapshot_id；自定义后端需自行解析和验证快照。 现有结束日股票池选择逻辑保持原样，样本外隔离和选择偏差仍需单独控制。

预算只统计评估尝试次数。集成测试脚本会记录真实 provider usage，但通用 Token 计费、自动 Agent runner 和独立研究 WebUI/REST 仍是后续能力。完整说明见英文指南。

发现、交接与显式重跑

先调用 assay_backend_list(probe=True)。返回值区分后端声明的能力与实际检查的可用性； 重启后尚未注册、但被历史数据集引用的后端也会列出。本地检查准备好的文件，远程检查 服务清单，均不保证任意指定期间的数据覆盖。适配器可选实现 describe() -> dict 和 probe() -> dict，原来只实现 evaluate() 的适配器仍可使用。

assay_research_context(session_id, limit=10) 提供剩余预算、失败统计、规范化表达式重复、 候选摘要与交接笔记，不返回指标时间序列。每个列表限制为 1–50 行，并标明截断情况； 单条文本没有 token 长度上限。候选按 RankIC 绝对值排序，仅便于查看，不代表统计验证； 表达式重复也不等于因子相关性。

backends = ws.list_backends(probe=True)
context = ws.research_context(session_id, limit=10)
manifest = ws.export_session(session_id)
assert ws.verify_manifest(manifest)
rerun = ws.replay_experiment(experiment_id, session_id,
                            request_id="explicit-rerun-1", agent="next-agent")

导出读取一致的 SQLite 快照，状态不变时哈希不变。清单含完整研究记录，不包含行情文件或 后端代码；哈希验证内容完整性，不验证来源身份。可用 assay_research_import 将清单恢复到另一工作区。重跑保留原 表达式、假设、配置哈希与 replay_of 来源关系，消耗新预算；也允许目标为配置完全一致的 另一会话。重复请求 ID 返回旧尝试。可变行情仍可能使结果变化，且不会恢复 Agent 的搜索树。

会话迁移

SDK 使用 target.import_session(manifest)，MCP 使用 assay_research_import(manifest)。 导入前验证版本、完整性、结构、数据集配置哈希、实验身份、来源关系和预算，再在单个事务中 写入。原 ID、请求 ID、笔记、时间戳与终态尝试均保留。相同清单重复导入具有幂等性；若目标 记录有冲突，包括目标会话已继续实验，则拒绝覆盖或合并。读取历史不需要后端已注册，继续 执行前需要注册对应后端并提供行情。

含 running 尝试的清单不能导入：先确认旧 worker 停止，显式 abandon，再重新导出。跨会话 replay_of 作为来源引用保留，不自动导入来源会话；来源可解析时会检查状态、表达式、假设和配置是否一致，检查支持两种导入顺序；如需查看缺失的来源，需单独导入其会话。 哈希不验证历史报告的真实性，记录迁移也不转移正在运行的 Agent、搜索树或行情。

导入不会自动停用源工作区。预算约束按工作区生效，迁移后应选择在哪个工作区继续。 这是研究快照复制，不提供分布式 worker 协调或跨工作区统一预算。

持久异步实验

配置 FactorDB controller 与 ADES worker 后，选择 backend="factordb_ades"，将后端探测返回的 data_version 填入 dataset 的 snapshot_id，并使用 adj="total"、as_of=end。 该后端拒绝评分窗口和自定义 backend options；具体 SDK 示例见英文指南。

实验返回 running 时，超时或重启后调用 assay_experiment_reconcile(experiment_id)， 或 REST POST /v1/research/experiments/{id}/reconcile。网页也提供 Reconcile asynchronous jobs。 协调操作复用原 job，不再扣尝试预算；普通读取和自动刷新只读取保存的记录。 任务完成、重试耗尽的回执可在跨库写入中断后恢复；租约 token 拒绝旧 worker 的迟到结果。

错误含 code、retryable、recommended_action。暂时故障保留运行状态；确定性输入错误结束当前尝试， 可创建带父实验关联的新修订。异步任务支持保存原因后取消，见下文。版本是逻辑标识，不认证物理数据内容； 结果是 FactorDB 聚合诊断。重启时应保留研究、registry 和 queue 数据库，导出记录不会复制行情或运行中的 worker。

组合记账协议

组合目标权重以交易前净值为基准。成交数量确定后，交易成本从现金扣除，持仓权重按扣费后的净值重新计算。不加杠杆的多头组合会预留交易费用；明确启用杠杆或多空交易的组合可以借款。新建组合评估数据集和实验记录 portfolio_accounting_protocol: cash-funded-v1，Agent 也可以从 Assay 后端能力中发现该协议。旧 session 可继续使用原数据集：历史记录保持不变，新实验记录当前协议。不同成本协议的结果会标记为不可直接比较；重放要求使用原协议。

新注册的数据集将 portfolio.initial_capital 设为市场货币计价的正数后，会自动启用历史流动性模型。每次调仓时，以当时组合净值计算订单金额，除以前 adv_window 个交易日（默认 20 日）未复权收盘价与成交量乘积的均值，得到订单参与率；执行日行情不参与计算。系统按 max_adv_fraction 限制成交，并根据实际成交参与率计算所配置的市场冲击。历史数据不足或缺失时，受影响订单会被阻断。partial_fill_handling="force" 会绕过容量上限，报告会提示。流动性记录包括数据覆盖、阻断订单和冲击是否生效。数据商可能修订历史行情，这一计算本身不保证历史版本的时点正确性。

美股和港股默认成交量单位为股；A 股必须显式填写 liquidity_volume_multiplier：Tushare 的手为 100，数据已按股计时为 1。例如 portfolio={"initial_capital": 1000000, "liquidity_volume_multiplier": 100}。显式设置 liquidity_model: null 可关闭自动流动性模型；未提供本金或参与率时，容量和市场冲击不生效，报告会提示。已有冻结数据集保持原设置。REST 组合回测的平铺参数在提供本金时自动启用；嵌套 config 按原配置重放，需要显式提供 liquidity_model 和成交量倍率。

账户工作区与共享资源

启用账户认证后，REST 和 HTTP MCP 根据认证账户选择独立的持久研究工作区；同一用户的登录和个人 API 密钥访问同一工作区。服务密钥继续访问原有共享服务工作区，应作为特权集成凭据保管。首次升级会为已有账户生成持久随机身份，原浏览器登录需重新登录；账户数据库和工作区数据应一起备份和恢复。此前实验版本中按数字用户 ID 建立的私人目录不会自动分配给新身份，需要管理员核实归属后迁移所需记录。历史共享会话仍保留在原工作区；管理员核实归属后，可以逐个导出并导入相应账户。本地 Python 和未启用认证的部署仍使用本地共享工作区。

研究数据集、会话、实验、笔记、研究因子注册表、因子库、已保存组合、临时面板会话和计算缓存按账户隔离。私人工作区可以复用本账户的研究面板和计算缓存。市场行情和物理计算资源仍共享。原有共享因子库及组合仍可由服务密钥访问，账户工作区使用各自的新存储。配置 FactorDB 与 ADES 后，个人账户可使用自己的 FactorDB 注册库及 factordb_ades 研究后端。任务、评分、因子元数据、相似度指纹和计算用量按账户隔离；ADES 队列及 worker 共享。执行任务的 worker 和服务器运维人员可以看到因子表达式，必须属于可信执行环境。ASSAY_FACTORDB_BUDGET_S 可设置每个账户的每日计算预算，在提交前检查；系统尚未提供硬性 CPU、内存和存储配额。临时面板 session 保存在单个进程中：同一 session 的请求需要路由到同一个 worker，服务重启后需重新创建；持久研究 session、已保存因子和组合可以跨进程及重启读取。

启用私人分布式研究时，在控制器配置 ASSAY_FACTORDB_DIR、ASSAY_QFV_PANEL_DIR 和 ASSAY_ADES=1，并通过 ASSAY_WORKER_KEYS 配置可信 worker。个人账户可用 /v1/fdb/markets 或 assay_backend_list(probe=true) 获取数据版本，再注册 backend="factordb_ades"、snapshot_id 为该版本、adj="total" 且 as_of 等于结束日的数据集，通过研究 REST 或 MCP 工具提交与恢复实验。个人 /v1/fdb/* 和 fdb_* 使用同一私有计算注册库；未启用 ADES 时，这些计算操作会提示私人后端不可用，本地 Assay 研究后端仍可使用。 私人 ADES 任务需要支持租约 token 的新版 worker。普通 ADES fdb_submit 可由客户端提供 request_id；重试时复用同一 ID 和完全相同的输入。REST POST /v1/fdb/submit 与 MCP fdb_submit 共用账户级请求记录，同一 ID 对应不同输入会返回冲突。不提供 ID 时重试可能产生第二个任务；非 ADES 模式暂不支持该参数。

取消异步实验

SDK：ws.cancel_experiment(experiment_id, "研究方向改变")；MCP： assay_experiment_cancel(experiment_id, reason)；REST： POST /v1/research/experiments/{id}/cancel，请求体为 {"reason":"研究方向改变"}。 网页选中运行中的异步实验，展开 Cancel an asynchronous experiment，填入原因后取消。

取消意图先持久保存，后端暂时不可用时仍保留为运行中；重启后使用 reconcile 接续取消， 首次原因不会被重试覆盖。排队任务停止派发，运行任务撤销租约，延迟派发和迟到结果也被拒绝。 已接受的完成回执优先保留。远端正在执行的原生计算可能仍会结束，取消不承诺立即中断 CPU 计算。

cancelled 是可导出、可作为修订父节点的终态，尝试预算不退还，不产生因子评分或失败缓存。 每日计算用量按已接受结果回执计入，已运行但被丢弃的计算时间尚未计量。 同步后端返回 CANCELLATION_UNSUPPORTED，需确认 worker 停止后再显式 abandon。

迁移完整研究任务

使用 assay_program_export 导出任务、关联 session、checkpoint、因子决策和跨窗口重评关系； 使用 assay_program_import 在另一工作区原子恢复。相同内容可安全重试，身份冲突或仍在运行的实验会被拒绝。 清单记录数据集配置，不包含行情文件或后端软件，继续执行前需另行准备。摘要用于完整性检查，不证明来源。
